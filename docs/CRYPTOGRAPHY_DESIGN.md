# gmailk-V 密碼學設計與二值化量化分析 (Cryptography & Fuzzy Commitment v3 Design)

> **最後更新**：2026-06-12  
> **參考理論**：Juels & Wattenberg, "A Fuzzy Commitment Scheme" (1999)

---

## 1. 核心設計思想與問題背景

在傳統的生物辨識系統中，直接儲存人臉特徵向量（例如 ArcFace 的 512 維浮點數）存在嚴重的隱私隱患：生物特徵是唯一且不可變更的，一旦資料庫洩漏，使用者的臉部特徵將終身失效。

**gmailk-V** 結合 **BioHash**（二值化與可撤銷投影）與 **Fuzzy Commitment v3** 模板保護機制，確保：
1.  **生物特徵不離設備**：原始人臉特徵向量不經網路傳送，也不存於資料庫中。
2.  **模板不可逆與可撤銷**：資料庫僅儲存 XOR 遮蔽後的 Sketch，洩漏時只需更換投影時間種子（Seed）即可廢止舊模板。
3.  **衍生對稱金鑰**：人臉不再是密碼，而是解鎖加密酬載（使用者姓名、權限等敏感資訊）的「衍生金鑰鑰匙」。

## 2. BioHash 投影與可靠位元選擇

### 2.1 數學步驟

```
  512-D 原始特徵 F ──────┐
                         ▼
  時間種子 (Seed) ───► 偽隨機產生器 ───► 2048×512 投影矩陣 M 
                                                │
                                                ▼
                                       X = M × F (2048-D)
                                                │
                                                ▼
                                       計算中位數 (Median)
                                                │
                                                ▼
                                          二值化 (0 / 1)
                                                │
                                                ▼
                                      選取前 511 位穩定位元 B
```

1.  **生成正交投影矩陣 $M$**：
    依據時間種子（如當天日期 `YYYYMMDDHHmm`），以 `std::mt19937` 隨機產生器在 $[-1.0, 1.0]$ 上均勻分佈填充生成大小為 **$2048 \times 512$** 的隨機投影矩陣 $M$。
2.  **隨機投影 (Random Projection)**：
    將 512 維正規化特徵向量 $F$ 乘上隨機矩陣 $M$，投影至更高維空間：
    $$X_{2048} = M_{2048 \times 512} \times F_{512}$$
3.  **中位數二值化 (Median Binarization)**：
    計算 $X$ 的中位數 $\text{median}$。進行二值化：若 $X_i > \text{median}$ 則 $b_i = 1$，否則 $b_i = 0$。
    *   **優勢**：中位數分割法保證輸出的 2048-bit 二進位序列中，`0` 和 `1` 的個數各佔 50%（Hamming Weight = 1024），資訊熵最大，能有效防止頻率分析攻擊。
4.  **可靠位元選擇 (Reliable Bit Selection)**：
    計算各投影分量與中位數的絕對距離 $|X_i - \text{median}|$。距離越遠，代表受噪聲干擾時位元越不容易翻轉。
    排序後挑選最穩定的前 **$511$** 個位元，記錄其在 2048 維中的索引位置 `indices`，以及對應的二值位元，組裝成 **$511$-bit 的人臉二值代碼 $B$**。

## 3. Fuzzy Commitment v3 方案

### 3.1 舊草案安全漏洞剖析 (高斯消去法方程式破解)

在早期的 v2 設計中，採用的是 Systematic BCH（系統線性碼），即：
$$\text{Codeword } C = [\text{Message } K \text{ (128-bit)} \ \Vert \ \text{Parity Bits } ECC \text{ (383-bit)}]$$
當時僅將 $K$ 與人臉指紋 $B$ 進行 XOR，而將 383-bit 的 ECC 以明文形式直接暴露存於資料庫：
$$\text{Stored} = \{ \text{indices}, \delta_{data} = B \oplus K, \delta_{ecc} = ECC \}$$
由於 BCH 校驗碼是透過生成矩陣的子矩陣 $G_{parity}$ 線性運算得到的：
$$[ECC_{1 \times 383}] = [K_{padded}] \times [G_{parity}]$$
攻擊者拿到明文 $ECC$ 後，可寫出以 $K$ 的 128 個位元為未知數、包含 383 個線性方程式的聯立方程組。利用**高斯消去法 (Gaussian Elimination)**，可在 1ms 內精確恢復出隨機金鑰 $K$，完全避開人臉比對，導致 Fuzzy Commitment 形同虛設。

### 3.2 v3 完美防護：全域 511-bit XOR 遮蔽

為了杜絕方程式破解，**整個碼字 $C$（包含資料區與校驗碼）都必須用人臉指紋 $B$ 全域 XOR 遮蔽**。

```
【註冊階段 (Enrollment)】
1. 生成 128-bit 真隨機金鑰 K (作為對稱加密金鑰)。
2. 使用 BCH(511, 233, t=42) 編碼 K：將 K 填充零至 26B，編碼生成 511-bit 碼字 C。
3. 計算 sketch δ (全域遮蔽)：δ = B (511-bit 人臉二值碼) ⊕ C (511-bit 碼字)。
4. 計算金鑰承諾 commitment h = SHA-256(K)。
5. 存入資料庫：模板 = {indices (1022B), sketch δ (64B), commitment h (32B), encrypted_payload}。
* 註冊完後，原始特徵向量與金鑰 K 立即抹除。

【驗證階段 (Verification)】
1. 提取現場人臉特徵，依據 indices 提取 511-bit 人臉指紋 B'。
2. 從模板讀取 sketch δ，執行解遮蔽操作取得帶噪聲碼字 C'：
   C' = B' ⊕ δ = B' ⊕ B ⊕ C = (B' ⊕ B) ⊕ C = e ⊕ C  (e 為人臉漢明誤差位元)
3. 將 C' 送入 BCH(511, 233, t=42) 解碼器：
   若現場的臉與註冊時的臉高度相似（漢明距離 e <= t=42 bits），BCH 糾錯算法將完全消去誤差，恢復原始金鑰 K*。
4. 驗證金鑰正確性：計算 SHA-256(K*) 並比對是否等於模板中的 commitment h。
   若一致，身分驗證成功，並以 K* 解密酬載。
```

## 4. BCH 參數選擇與量化分析 (t=42 評估)

BCH 碼由三個參數定義：$(n, k, t)$。在 Galois Field $GF(2^9)$ 下：
1.  **$n$ (碼字長度)**：$n = 2^9 - 1 = \mathbf{511}$ bits。
2.  **$t$ (最大糾錯能力)**：我們容許的最大漢明距離誤差。
3.  **$k$ (資料長度)**：金鑰 $K$ 存放的空間大小。
$$\text{公式限制：} k \ge n - m \times t = 511 - 9t$$
由於對稱金鑰 $K$ 必須是 128 bits，意即 $k \ge 128$。經計算：
$$511 - 9t \ge 128 \implies 9t \le 383 \implies t \le 42.5$$
因此，在 $GF(2^9)$ 且金鑰長度 128-bit 的約束下，糾錯閾值的最大極限為 **$t = 42$**。

### 4.1 本人與路人漢明距離量化分佈

透過模擬器與在 CV181X 邊緣端收集的真實 ArcFace 特徵數據分析：

*   **本人比對 (Genuine Matches)**：在不同光線、微小轉頭與表情變化下，同一個人的兩次二值指紋漢明距離**最大僅為 14 bits**（中位數集中在 5~8 bits）。
*   **路人比對 (Imposter Matches)**：由於二值化保證了最大熵，不同人臉間的二值代碼呈現完全隨機獨立性，其漢明距離符合二項式分佈 $B(511, 0.5)$，期望值落在 **255 bits** 附近。

```
 本人分佈 (Genuine)                路人分佈 (Imposter)
     ┌─┐
     │ │                                    ┌─┐
    ─┘ └───────┬────────────────────────────┘ └─
  0   14      t=42                         255      511  (漢明距離)
   [OK區]     [糾錯門檻]                   [期望值]
```

### 4.2 設定 $t=42$ 的安全指標

*   **FRR (錯誤拒絕率)**：由於本人最大誤差 14 bits 遠小於糾錯閾值 42，系統的 **FRR = 0.00%**，保證了本人驗證的高通過率與極佳體驗。
*   **FAR (錯誤接受率)**：路人漢明距離小於等於 42 的概率在數學上等同於硬幣投擲 511 次中反面次數小於等於 42 的機率：
    $$P(e \le 42) = \sum_{i=0}^{42} \binom{511}{i} 0.5^{511} \approx 2.47 \times 10^{-37}$$
    在統計學上，**FAR = 0.00%**，達到軍規級防偽安全性。

## 5. 序列化模板格式 (v3)

Fuzzy Commitment v3 序列化模板在資料庫中以 Hex 字串儲存，總長度依加密酬載長度而變。

```
03 30 0006 000a 000c ... 07fb 07fc  94a9...577b   003c...4c00  003f  aaac...eaf
│  │  └────────────────────────┘    └──────────┘  └──────────┘  │     └───────┘
│  │         ③ Indices              ④ Sketch    ⑤ Commitment │     ⑦ Encrypted
│  │         511×2B=1022B            δ=B⊕C 64B    SHA256(K) 32B │      Payload
│  │                                                            │       63B
│  └─ ② ECC Length: 48 bytes (0x30)                            │
└──── ① Version: 3 (v3 全域XOR)                                └─ ⑥ PayloadLen=63
```

### 5.1 欄位對照表

| # | 欄位名稱 | Byte 範圍 | 大小 | 數值範例與說明 |
|---|---|---|---|---|
| **①** | **Version** | `[0]` | 1B | `0x03`：代表 v3 全域 XOR 遮蔽格式。 |
| **②** | **ECC Length** | `[1]` | 1B | `0x30` (48 bytes)：BCH 糾錯校驗碼位元組長度。 |
| **③** | **Indices** | `[2..1023]` | 1022B | **511 個** 2-byte 大端序整數，代表從 2048 維投影中挑選的最穩定可靠位元索引，已按升序重排。 |
| **④** | **Sketch $\delta$** | `[1024..1087]` | 64B | **511-bit 全域 XOR 遮蔽結果**（$B \oplus C$，遮蔽了隨機碼字）。 |
| **⑤** | **Commitment $h$** | `[1088..1119]` | 32B | **SHA-256(K)** 金鑰承諾，用於驗證糾錯恢復的金鑰是否正確。 |
| **⑥** | **Payload Length** | `[1120..1121]` | 2B | 加密酬載的位元組長度（大端序）。`0x0000` 表示無酬載。 |
| **⑦** | **Encrypted Payload** | `[1122..]` | 變長 | 加密酬載的對稱認證加密 (Encrypt-then-MAC) 封裝結構，如下所示。 |

### 5.2 加密酬載結構 (Encrypted Payload Structure)

加密酬載採用 **AES-128-CTR + HMAC-SHA256** 進行保護：

| 子欄位 | 大小 | 說明 |
|:---|:---|:---|
| **IV (初始化向量)** | 16B | 真隨機產生的 AES CTR 初始計數值。 |
| **Ciphertext (密文)** | $N$ Bytes | AES-128-CTR 加密後的元數據明文（如使用者資訊 JSON）。 |
| **HMAC-SHA256 (驗證碼)** | 32B | $\text{HMAC-SHA256}(K, IV \Vert Ciphertext)$，防止密文遭到惡意篡改。 |
