## 1. 系統中的 BCH 參數與限制

BCH 是一種建立在伽羅瓦體 (Galois Field, $GF(2^m)$) 上的線性區塊碼。一組 BCH 碼由三個參數定義：**$(n, k, t)$**。
在我們的系統中，預設使用 $m=9$：

1. **$n$ (Block Length，碼字總長度)**：$n = 2^m - 1 = \mathbf{511}$ bits。
2. **$t$ (Error Correction，最大容錯能力)**：我們容許的最大錯誤位元數 (例如 $t=25$)。
3. **$k$ (Message Length，資料長度)**：扣除校驗碼 (ECC) 後，可用來放金鑰 $K$ 的空間。

**參數綁定公式**：每糾正 1 bit 錯誤，最多需要花費 $m$ bits 的空間來放 ECC。
$$k \ge n - m \times t$$

### 為什麼參數不能隨便調？

我們的系統規定，金鑰 $K$ (`BIOHASH_K_BYTES`) 必須是 **128 bits**。這代表上面算出來的 $k$ **絕對不能小於 128**。

- 如果設 $t=25$：$k \ge 511 - (9 \times 25) = 286$。因為 $286 > 128$，空間足夠，多出來的空間會補零 (Padding)。
- 如果設 $t=45$：$k \ge 511 - (9 \times 45) = 106$。因為 $106 < 128$，128 bits 的金鑰會「塞不進去」，導致系統崩潰。
  **結論**：在 $n=511$ 的前提下，安全的容錯調整範圍約在 **$t = 0 \sim 42$** 之間。

## 2. 安全漏洞剖析與修復 (2048 維度擴展)

### 2.1 先前草案的致命漏洞：高斯消去法破解 (Gaussian Elimination)

在先前的設計中，人臉指紋 $B$ 只取了 128 bits。為了湊成長度，我們只把碼字 $C$ 前面的資料部分 (128 bits) 與 $B$ 進行 XOR，然後把 383 bits 的 ECC **以明文形式** 直接接在後面存進資料庫。

**駭客視角的數學破解原理**：
BCH 是「系統線性碼 (Systematic Linear Code)」。這意味著校驗碼 ECC 是透過原始金鑰 $K_{padded}$ 乘上一個公開的「生成矩陣 (Generator Matrix $G$)」得到的。
$$[ECC_{1 \times 383}] = [K_{1 \times 128} \ | \ 0_{1 \times 158}] \times [G_{parity}]$$

如果駭客拿到了資料庫中的 383 bits ECC 明文，他就可以寫出聯立方程式。例如：

- $e_1 = g_{1,1}k_1 \oplus g_{1,2}k_2 \oplus \dots \oplus g_{1,128}k_{128}$
- $e_2 = g_{2,1}k_1 \oplus g_{2,2}k_2 \oplus \dots \oplus g_{2,128}k_{128}$
- $\dots$
- $e_{383} = \dots$

在這裡，$e_i$ (明文 ECC) 與 $g_{i,j}$ (標準 BCH 矩陣) 都是**已知常數**。未知的只有 $K$ 的 128 個位元 ($k_1 \dots k_{128}$)。
駭客擁有 383 個方程式，卻只有 128 個未知數，矩陣秩 (Rank) 遠大於 128。他只需要使用高中教的**高斯消去法 (Gaussian Elimination)**，在一般筆電上不到 1 毫秒 (ms) 就能 100% 準確地求出金鑰 $K$。
**結果**：駭客完全不需要取得您的人臉 $B$，直接破解加密酬載。Fuzzy Commitment 形同虛設。

### 2.2 正確解法：長度對齊與 $2048 \times 512$ 投影擴展

要防止聯立方程式被解開，**整個碼字 $C$ (包含 ECC) 都必須被 XOR 遮蔽**。因此，$B$ 的長度必須與 $C$ 的長度 ($511$ bits) 完全一致。

**如何取得 511 bits 的高可靠指紋？**

1. 將原本 $512 \times 512$ 的隨機投影矩陣，擴增為 **$2048 \times 512$**。
2. ArcFace 的 512 維浮點數特徵，乘上這個巨大的矩陣後，會產生 **2048 個浮點數**。
3. 我們計算這 2048 個數值與「中位數」的絕對值距離，由大到小排序。
4. 挑出距離最遠（最穩定）的 **511 個位元**，作為新的人臉指紋 $B$。
5. 執行全域遮蔽：$sketch_{511} = B_{511} \oplus C_{511}$。

**統計學原理與效能**：
因為母體擴大了 4 倍 (512 $\rightarrow$ 2048)，從中挑出的前 25% (511 個位元)，其「穩定度」與原本從 512 中挑選 128 是完全相同的。
效能上，1 百萬次的浮點乘加運算在 CV181X ARM 處理器上僅需極少數毫秒，記憶體佔用約 4MB，且最耗時的 ArcFace TPU 模型**不需重複執行**。這是一個幾乎無效能損失的完美修復方案。

## 3. 量化分析與最佳平衡點實作指南

為確保升級到 511 bits 後系統依舊可靠，我們必須透過 Python 執行量化模擬，找出最佳的 `BCH_T` 值，也就是能讓 **FAR (錯誤接受率)** 與 **FRR (錯誤拒絕率)** 達到平衡的 EER (Equal Error Rate) 點。

### Step 1: 數據準備 (Data Preparation)

由於必須模擬真實物理環境的噪聲，我們不能只用隨機數，必須收集真實的 ArcFace 512 維度浮點數特徵 (`std::vector<float>`)。

- **Genuine (本人資料集)**：撰寫一個小工具在 CV181X 上運行，讓您對著鏡頭轉頭、改變表情、在不同光線下，收集 100~200 筆您本人的 512-D 特徵，匯出成 CSV 或 JSON。
- **Imposter (路人資料集)**：透過公開資料集 (如 LFW)，使用您的 `arcface.cvimodel` 在 PC 端或設備端提取 1000 筆不同人臉的 512-D 特徵。

### Step 2: 建立 Python 核心模擬器

在 `bioh-bch/` 目錄下建立 `simulate_biohash.py`。

1. **產生隨機種子與矩陣**：使用 NumPy 產生固定的 $2048 \times 512$ 投影矩陣。
2. **模擬特徵提取流水線**：
   ```python
   def extract_biohash_b(feature_512, matrix_2048x512):
       # 1. 矩陣相乘
       projected = np.dot(matrix_2048x512, feature_512)
       # 2. 計算中位數與二值化
       median = np.median(projected)
       bits = (projected > median).astype(int)
       # 3. 挑選最強 511 位元
       distances = np.abs(projected - median)
       top_511_indices = np.argsort(distances)[::-1][:511]
       b_511 = bits[top_511_indices]
       return b_511, top_511_indices
   ```

### Step 3: 計算 Hamming Distance (漢明距離)

- **本人比對 (Genuine Matches)**：將您自己的 100 筆資料「兩兩配對」，計算這 511 bits 中有多少個 bits 不同。記錄下所有的距離值 (例如通常錯 30~50 bits)。
- **路人比對 (Imposter Matches)**：將您的 1 筆註冊資料，與 1000 個路人進行配對，計算距離值 (隨機期望值應落在 $511 / 2 \approx 255$ 附近)。

### Step 4: 繪製分佈直方圖與評估

使用 `matplotlib` 將這兩組距離畫在同一張直方圖上：

1. **理想狀態**：左側有一座山峰 (Genuine，集中在低錯誤區)，右側有一座山峰 (Imposter，集中在高錯誤區)。兩座山峰中間有一個明顯的「空谷」。
2. **決定 BCH_T**：
   我們在空谷中畫一條垂直線，這條線的 X 軸數值就是我們要在 C++ 程式中設定的 `BCH_T`！
   - 掃描範圍：假設 $t$ 設為 $10, 15, 20 \dots 40$。
   - 計算每個 $t$ 之下的 **FAR**：路人山峰中有多少比例越過了 $t$ (跑到左邊)？
   - 計算每個 $t$ 之下的 **FRR**：本人山峰中有多少比例越過了 $t$ (跑到右邊)？
3. **產出結論**：選擇一個讓 FAR 趨近於 0.00% 且 FRR 維持在可接受範圍 (如 < 5%) 的 $t$ 值。

完成上述分析後，我們就能帶著確鑿的數據，安心地將 $2048 \times 512$ 與算出的 $t$ 值寫進 CV181X 的 C++ 原始碼中！
